Selected work / Inventory event reconciliation

Case study · Public engineering lab

Reconciling inventory when events arrive twice or go missing.

This runnable lab shows two different recovery steps: identify duplicate deliveries before applying them, and compare the resulting inventory state with a snapshot when an event may be missing.

Open the GitHub repository →
Project typePublic demonstration
RoleMaintainer and reviewer
EvidenceSource code and synthetic scenarios

The problem.

Software can record the same movement twice or miss it entirely. Either error can leave the displayed stock count out of step with the warehouse.

What the lab demonstrates.

The lab stores event identities so applying the same delivery twice does not change inventory a second time. Sequence checks make gaps visible. Snapshot watermarks help the lab distinguish updates already reflected in the snapshot from updates that still need to be applied.

What it does not claim.

Examples are synthetic. This is not a production benchmark, and it includes no employer code, customer records, or production measurements. The repository discloses AI development assistance.
